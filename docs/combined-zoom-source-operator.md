# Combined operator enrollment selection

The existing `exitspec.source_authoring_operator` accepts `--enroll-metadata` to select the reviewed two-person numeric roster enrollment on the same source app and Zoom runtime. Omitting the flag retains direct numeric pairing. This flag grants no launch or network authority.

The installed production Fireworks serving registry remains empty. Without an explicit leading `--demo`, the combined entrypoint refuses before parsing approval paths or reading terminal input, including with the enrollment flag. The separately typed, exact-candidate demo approval uses local accounting and one persistent attempt; it does not qualify production serving. See [the staged-demo runbook](staged-demo-runbook.md) for the distinct guarantee and live-authorization requirements. Offline test fixtures are not installable qualifications.

When a future qualified launch is admitted, metadata consent, browser capture consent, and exact-source Fireworks acknowledgment remain separate. Enrollment uses the existing hidden TTY boundary and adopts the same child, stream, POC ownership and original cumulative deadline. Enrollment refusal, timeout or owner closure unwinds the combined bootstrap and revokes its Fireworks launch and Zoom resources. The existing server shutdown also closes both resources. After capture, the original Zoom deadline does not become a new Fireworks allowance; source drafting retains its independent admission, consent, one-use operation and budget controls.

Public provider behavior is still unqualified: useful Zoom metadata before media readiness and real transcript delivery must be observed under separate authorization, and Fireworks token counts alone do not establish token-sequence or chat-template parity. Missing metadata refuses without a media fallback. This wiring changes no frontend, serving profile, request body, tokenizer verification, provider transport or frozen diagnostic packet.
